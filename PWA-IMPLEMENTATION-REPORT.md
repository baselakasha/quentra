# Quentra PWA + Offline Sync — Implementation Report

**Date**: 2026-05-23  
**Scope**: Add PWA shell + full offline support + background sync to the existing Angular 20 frontend. Zero changes to web behavior. No Xcode, no Apple Developer account required.

---

## 1. How It Works End-to-End

```
User action
    │
    ▼
IndexedDB (local store) ──── always read from here ────▶ UI
    │
    │  immediately write here too
    ▼
Sync Queue (IndexedDB)
    │
    │  when online
    ▼
REST API (/api/budget, /api/category)
    │
    │  server response
    ▼
IndexedDB updated ──── UI refreshes
```

- **Reads**: always from local IndexedDB. Never block on network.
- **Writes**: write to IndexedDB first, emit to UI, queue the HTTP call.
- **Sync**: a background `SyncService` drains the queue when online.
- **PWA shell**: Angular's built-in `@angular/pwa` caches the app bundle so the UI loads even with no network.

## 3. IndexedDB Schema (`db.service.ts`)

Three object stores mirror the server data model plus one queue store.

```typescript
// db.service.ts
import { openDB, DBSchema, IDBPDatabase } from 'idb';

interface QuentraDB extends DBSchema {
  budgets: {
    key: string;      // budget.id (UUID)
    value: LocalBudget;
    indexes: { 'by-pinned': number };
  };
  categories: {
    key: string;      // category.id (UUID)
    value: LocalCategory;
    indexes: { 'by-budget': string };
  };
  meta: {
    key: string;      // arbitrary keys: 'lastSync', 'userId'
    value: unknown;
  };
  syncQueue: {
    key: number;      // auto-increment
    value: SyncOperation;
    indexes: { 'by-status': string };
  };
}

interface LocalBudget {
  id: string;
  name: string;
  startDate: string;
  endDate: string;
  monthlyIncome: number | null;
  isPinned: boolean;
  // sync bookkeeping
  _dirty: boolean;       // has pending local changes
  _deleted: boolean;     // soft-deleted, waiting to sync
  _isNew: boolean;       // created offline, not on server yet
  _syncedAt: string;     // last time server confirmed this record
}

interface LocalCategory {
  id: string;
  budgetId: string;     // denormalized for easy lookup
  name: string;
  plannedAmount: number;
  spentAmount: number;
  order: number;
  type: 'need' | 'want';
  // sync bookkeeping (same as above)
  _dirty: boolean;
  _deleted: boolean;
  _isNew: boolean;
  _syncedAt: string;
}

// One entry per pending API call
interface SyncOperation {
  id?: number;          // auto-increment PK
  status: 'pending' | 'failed';
  retries: number;
  createdAt: string;
  operation: 'budget:create' | 'budget:update' | 'budget:delete'
           | 'budget:pin'    | 'budget:unpin'  | 'budget:duplicate'
           | 'category:create' | 'category:update' | 'category:delete'
           | 'category:order';
  entityId: string;
  payload: unknown;   // matches the relevant request body type
}
```

## 6. Refactoring `BudgetService`

The service becomes local-first. HTTP is still used but only for sync, not for reads.

```typescript
// Before (current)
getBudgets(): Observable<Budget[]> {
  return this.http.get<Budget[]>(`${this.apiUrl}/budget`);
}

// After (local-first)
getBudgets(sortField?: string, sortDirection?: 'asc' | 'desc'): Observable<Budget[]> {
  return from(this.db.getBudgets()).pipe(
    map(localBudgets => {
      const active = localBudgets.filter(b => !b._deleted);
      return this.sortBudgets(active, sortField, sortDirection);
    })
  );
}
```

```typescript
// Before
createBudget(data: CreateBudgetRequest): Observable<Budget> {
  return this.http.post<Budget>(`${this.apiUrl}/budget`, data);
}

// After
createBudget(data: CreateBudgetRequest): Observable<Budget> {
  const id = crypto.randomUUID();
  const localBudget: LocalBudget = {
    ...data,
    id,
    isPinned: false,
    monthlyIncome: data.monthlyIncome ?? null,
    _dirty: true, _isNew: true, _deleted: false, _syncedAt: ''
  };

  return from(
    this.db.saveBudget(localBudget).then(() =>
      this.db.enqueue({
        operation: 'budget:create',
        entityId: id,
        payload: { ...data, id },   // send client-generated id
        status: 'pending', retries: 0, createdAt: new Date().toISOString()
      })
    )
  ).pipe(
    map(() => this.toApiBudget(localBudget)),
    tap(() => { if (this.network.isOnline) this.sync.triggerSync(); })
  );
}
```

Same pattern applies to `updateBudget`, `deleteBudget`, `pinBudget`, `unpinBudget`, `duplicateBudget`.

The `getBudgetById` read also becomes local:
```typescript
getBudgetById(id: string): Observable<Budget> {
  return from(this.db.getBudgetById(id)).pipe(
    map(b => {
      if (!b) throw new Error('Budget not found');
      return this.toApiBudget(b);
    })
  );
}
```

`calculateBudgetSummary` and `getBudgetsWithSummaries` — **no changes**, they work on the Budget objects regardless of source.

## 8. `SyncService`

This is the heart of offline sync. It runs on app startup and whenever the network comes back.

```typescript
@Injectable({ providedIn: 'root' })
export class SyncService {
  private syncing = false;

  constructor(
    private db: DbService,
    private http: HttpClient,
    private network: NetworkService
  ) {}

  init() {
    // Sync on every transition from offline → online
    this.network.online$.pipe(
      filter(online => online),
      distinctUntilChanged()
    ).subscribe(() => this.sync());

    // Also sync on startup if already online
    if (this.network.isOnline) this.sync();
  }

  triggerSync() {
    this.sync();
  }

  private async sync() {
    if (this.syncing) return;
    this.syncing = true;
    try {
      await this.pushQueue();
      await this.pullChanges();
    } finally {
      this.syncing = false;
    }
  }

  // --- PUSH: send queued local changes to server ---

  private async pushQueue() {
    const ops = await this.db.getPendingOps();

    // Deduplicate: for update ops on the same entity, keep only latest
    const deduplicated = this.deduplicateOps(ops);

    for (const op of deduplicated) {
      try {
        await this.executeOp(op);
        await this.db.markOpDone(op.id!);
      } catch (err: any) {
        // 404 on delete = already gone, treat as success
        if (op.operation.endsWith(':delete') && err?.status === 404) {
          await this.db.markOpDone(op.id!);
        } else if (err?.status === 409 || err?.status === 400) {
          // Conflict or validation error — mark failed, don't retry
          await this.db.markOpFailed(op.id!);
        } else {
          // Network error — leave as pending, retry next sync
          break;
        }
      }
    }
  }

  private async executeOp(op: SyncOperation): Promise<void> {
    const base = '/api';
    switch (op.operation) {
      case 'budget:create':
        await firstValueFrom(this.http.post(`${base}/budget`, op.payload));
        break;
      case 'budget:update':
        await firstValueFrom(this.http.put(`${base}/budget/${op.entityId}`, op.payload));
        break;
      case 'budget:delete':
        await firstValueFrom(this.http.delete(`${base}/budget/${op.entityId}`));
        break;
      case 'budget:pin':
        await firstValueFrom(this.http.put(`${base}/budget/${op.entityId}/pin`, {}));
        break;
      case 'budget:unpin':
        await firstValueFrom(this.http.put(`${base}/budget/${op.entityId}/unpin`, {}));
        break;
      case 'budget:duplicate':
        await firstValueFrom(this.http.post(`${base}/budget/${op.entityId}/duplicate`, {}));
        break;
      case 'category:create':
        await firstValueFrom(this.http.post(`${base}/category`, op.payload));
        break;
      case 'category:update':
        await firstValueFrom(this.http.put(`${base}/category/${op.entityId}`, op.payload));
        break;
      case 'category:delete':
        await firstValueFrom(this.http.delete(`${base}/category/${op.entityId}`));
        break;
      case 'category:order':
        await firstValueFrom(this.http.put(`${base}/category/order`, op.payload));
        break;
    }
  }

  // --- PULL: fetch server changes since last sync ---

  private async pullChanges() {
    const lastSync = await this.db.getLastSync();
    const since = lastSync ? lastSync.toISOString() : '';
    const url = since ? `/api/budget?since=${since}` : '/api/budget';

    const budgets = await firstValueFrom(this.http.get<any[]>(url));

    for (const budget of budgets) {
      const existing = await this.db.getBudgetById(budget.id);
      // Don't overwrite records with unsent local changes
      if (existing?._dirty) continue;

      await this.db.saveBudget({
        ...budget,
        monthlyIncome: budget.monthlyIncome ? Number(budget.monthlyIncome) : null,
        _dirty: false, _isNew: false, _deleted: false,
        _syncedAt: new Date().toISOString()
      });

      for (const cat of (budget.categories ?? [])) {
        const existingCat = await this.db.getCategoryById(cat.id);
        if (existingCat?._dirty) continue;
        await this.db.saveCategory({
          ...cat,
          budgetId: budget.id,
          plannedAmount: Number(cat.plannedAmount),
          spentAmount: Number(cat.spentAmount),
          _dirty: false, _isNew: false, _deleted: false,
          _syncedAt: new Date().toISOString()
        });
      }
    }

    await this.db.setLastSync(new Date());
  }

  // Deduplicate: if multiple updates for same entity, keep the last one.
  // If create + update for same entity, merge into the create payload.
  // For category:order ops on the same budget, keep only the latest.
  private deduplicateOps(ops: SyncOperation[]): SyncOperation[] {
    const seen = new Map<string, SyncOperation>();
    for (const op of ops) {
      const key = `${op.operation}:${op.entityId}`;
      seen.set(key, op); // later op overwrites earlier
    }
    return [...seen.values()];
  }
}
```

## 9. `AuthService` Changes

The only change here is reading the token in a way that stays synchronous (localStorage is fine for token on web — it's only native iOS where Keychain matters, and we're not doing native).

**What changes**: Cache the `/auth/me` response locally so `getCurrentUser()` works offline.

```typescript
// Add to auth.service.ts
async cacheCurrentUser(user: UserInfo): Promise<void> {
  localStorage.setItem('cachedUser', JSON.stringify(user));
}

getCachedUser(): UserInfo | null {
  const cached = localStorage.getItem('cachedUser');
  return cached ? JSON.parse(cached) : null;
}

getCurrentUser(): Observable<UserInfo> {
  return this.http.get<UserInfo>(`${this.apiUrl}/auth/me`).pipe(
    tap(user => this.cacheCurrentUser(user))
  );
}

getCurrentUserOfflineFallback(): Observable<UserInfo> {
  if (this.networkService.isOnline) {
    return this.getCurrentUser();
  }
  const cached = this.getCachedUser();
  return cached ? of(cached) : throwError(() => new Error('Offline'));
}
```

Header component calls `getCurrentUserOfflineFallback()` instead of `getCurrentUser()`.

## 12. Conflict Resolution Strategy

For a **single-user personal app**, conflicts are rare. Strategy:

| Scenario | Resolution |
|----------|-----------|
| Edited same budget on web + phone while offline | Last-write-wins. Server timestamp wins on pull. Local dirty records skip overwrite until pushed. |
| Deleted on web, edited on phone offline | Delete wins. On sync push, the edit gets 404. Mark op failed silently. |
| Created budget offline, name already exists on server | Push gets 409. Mark failed, show user a notification to rename. |
| Pin offline, different budget pinned on server | Push the pin op. Server handles the unpin-all-then-pin transaction correctly. |
| Category order changed on both sides | Last-write-wins. The final `category:order` op pushed wins. |

**Key rule in `pullChanges()`**: never overwrite a `_dirty: true` local record with server data. Push first, then pull.

## 15. Recommended Implementation Order

1. **Deploy to HTTPS first** — get the current web app live. Everything else is easier to test on a real URL.
2. **`ng add @angular/pwa`** — get the install banner working in Safari before adding offline logic.
3. **`NetworkService` + `DbService`** — foundation layer. Test IndexedDB reads/writes in isolation.
4. **Refactor `BudgetService`** — start with read path (`getBudgets`, `getBudgetById`), confirm UI works from local DB.
5. **Refactor write paths** — `createBudget`, `updateBudget`, `deleteBudget`, then pin/unpin/duplicate.
6. **`CategoryService`** — same pattern as budget.
7. **`SyncService` push** — queue drain. Test with DevTools → Network → Offline.
8. **Backend `updatedAt` + `?since=`** — can be done in parallel with frontend work.
9. **`SyncService` pull** — incremental sync on reconnect.
10. **Auth offline cache** — last, it's a polish step.
